# 网盘离线下载助手

一个 Manifest V3 浏览器扩展：识别网页中的磁力链接，或从扩展弹窗批量提交链接到 **123云盘 / PikPak**。支持分别设置默认保存目录、临时覆盖目录及登录凭证同步。

> 本项目不是网盘官方客户端，与相关服务商无隶属关系。使用非官方接口，接口、登录凭证结构和服务限制可能变化。请仅下载你拥有权利或已获许可的内容，并遵守服务条款。

## 安装与使用

1. 下载或克隆本仓库，保留完整目录结构。
2. 在 Chrome 打开 `chrome://extensions`，或在 Edge 打开 `edge://extensions`，启用开发者模式。
3. 选择“加载已解压的扩展程序”，选择包含根目录 [manifest.json](<manifest.json>) 的文件夹。**无需构建，也无需先安装 npm 依赖。**
4. 如已安装同类油猴脚本，先停用，避免重复按钮。
5. 点击扩展图标进入设置，打开对应网盘主页并自行登录。保持网盘页打开，等待同步；也可点击“立即同步 Token”。安装或重新加载扩展后，已有网页可能需要刷新。
6. 返回扩展设置检查状态，再使用网页磁力链接旁的“离线下载”按钮，或在批量面板中每行输入一条链接、勾选目标网盘并提交。

“立即同步”可能打开或刷新网盘标签页；操作完成不等于已取得有效凭证，应以状态显示和实际提交结果为准。扩展不要求输入网盘密码。

### 保存目录与结果

- 设置中的文件夹 ID 是该网盘的默认目录；填写的是 **ID，不是目录名称或完整网页地址**。
- 提交时填写临时目录 ID 可覆盖默认值；留空则使用已保存的默认目录，不表示强制回到根目录。
- 清除默认目录后，123云盘提交不带目录参数，由服务端决定位置；PikPak 使用下载目录。
- 结果按网盘显示成功、失败、跳过和文件数。凭证类错误会提前终止该网盘剩余链接；成功 + 失败 + 跳过 = 总数。同一批次中完全相同的链接会去重。
- “提交成功”表示接口接受任务，**不保证远端下载完成**；请到网盘中确认任务状态、文件及保存位置。

## 功能边界

- 自动按钮识别 `<a href="magnet:...">`；不扫描纯文本磁力串，也不保证覆盖 iframe、网页 Shadow DOM 或浏览器受限制页面。
- 批量链接能否被接受取决于目标网盘支持的格式、账号权益、额度和资源可用性。
- 登录状态徽标主要依据本地凭证和时间信息，不是每次都向服务端验证凭证。
- PikPak 凭证刷新可能轮换 refresh token；网页会话可能需要重新登录。网页登录退出不保证同步清空扩展中的旧凭证。

## 隐私与权限

- 凭证、设备标识、同步时间和目录设置保存在 **`chrome.storage.local`，扩展没有额外加密**。这不是密码保险箱；不要共享浏览器用户目录、扩展存储导出或带凭证的调试日志。
- 网盘页面内容脚本读取网页本地登录态，约每 2 秒检查一次并合并写入扩展存储；不是通过本项目自建服务器中转。
- 扩展业务请求仅发往对应网盘服务，包括登录凭证刷新、接口校验、链接解析和任务提交。选中的网盘将收到待下载链接、目标目录以及该服务必要的凭证/设备信息。普通网页扫描不代表会自动提交所有发现的链接。
- 当前代码未设置独立的统计或遥测上传服务。这不改变网盘服务自身的隐私政策，也不意味着请求只发生在最终任务提交那一步。
- `storage` 用于保存上述状态；`tabs` 用于查找、打开和刷新网盘标签页。
- `<all_urls>` 主机权限范围很宽：后台用于访问网盘接口，HTTP/HTTPS 页面内容脚本用于识别磁力链接。浏览器可能提示可读取和更改网站数据；实际匹配范围以 [manifest.json](<manifest.json>) 为准。可在浏览器扩展设置限制网站访问，但这可能影响按钮和登录同步。
- 当前界面没有“一键退出并删除所有凭证”功能。停止使用时可移除扩展以清除其本地存储；如怀疑凭证泄露，还应在网盘账户端撤销会话或重新登录。

## 打包与发布（Windows）

开发时直接加载源码即可；提交 Chrome Web Store / Microsoft Edge Add-ons 时通常上传 ZIP，由商店审核并分发，不需要自行生成 CRX。

安装 Node.js >= 20 后，双击根目录 [release.bat](<release.bat>)，或运行：

```bat
release.bat
rem 自动化执行，不等待按键：
release.bat --no-pause
```

批处理调用 [打包脚本](<scripts/release.ps1>)，检查 Node 版本及扩展版本号格式，执行 JavaScript 语法、模块引用与扩展资源路径检查，然后生成 ZIP 并核对归档结构，最后生成 SHA-256 校验文件。任一步失败返回非零退出码；成功产物位于 `dist/`，文件名包含版本号和时间戳，不覆盖旧发布包。当前工程没有自动测试目录，发布流程不执行单元测试。

ZIP 根目录包含 manifest 和运行源码，同时收录现有 README；LICENSE、NOTICE、THIRD_PARTY_NOTICES 等说明文件仅在存在时收录，不要求恢复已删除文件。不会打包开发脚本、Git 元数据或历史发布包；不会混淆代码、生成私钥或自动上传商店。

发布新版本只需更新 [manifest.json](<manifest.json>) 的 `version`，再运行脚本；它是唯一版本来源。商店更新须使用比已发布版本更高的版本号。

- **GitHub Releases**：上传 ZIP 和校验文件；用户解压后通过开发者模式加载。
- **扩展商店**：上传 ZIP，补充商店资料、截图、隐私政策及权限用途说明，提交审核。打包成功不等于审核通过或已发布。
- 上传前须核实第三方许可证，并对最终 ZIP 解压后的扩展进行真实浏览器回归。脚本不会替你完成这些检查。

## 开发与目录

开发检查要求 **Node.js >= 20**；不需要 npm 或依赖安装，项目不保留 package.json。浏览器运行扩展不需要 Node.js。

```sh
node scripts/check.mjs
```

静态检查覆盖现有源码与脚本的 JavaScript 语法、相对模块引用、manifest 及弹窗资源路径。它不验证真实登录态、网盘接口或浏览器交互。

### 发布前浏览器回归

将最终 ZIP 解压到新目录，在 Chrome / Edge 中加载该目录，检查：

1. 扩展能够加载，后台与弹窗没有报错。
2. 两个网盘的登录态同步、默认目录保存和重新打开后的回显正常。
3. 网页磁力按钮、动态新增链接、弹窗打开与关闭正常。
4. 使用有权下载的测试链接验证单条和批量提交、临时目录覆盖及失败提示。
5. 到网盘确认实际任务和保存位置；提交成功不代表下载完成。

静态检查与打包成功不能替代上述手动验证。

```text
manifest.json
src/
  background/index.mjs       # MV3 消息分发、后台入口
  core/
    storage.mjs             # 状态读取、合并保存、目录设置
    http.mjs                # 通用 JSON 请求
    offline.mjs             # 状态聚合、批量编排、同步入口
  providers/
    index.mjs               # 适配器注册
    pan123.mjs              # 123云盘适配器
    pikpak.mjs              # PikPak 适配器
  content/
    drive.js                # 网盘页面登录态同步
    magnet.js               # 网页磁力按钮和弹窗
  ui/panel.js               # 共享面板
  popup/
    index.html
    index.js
    index.css
  vendor/md5.mjs             # 第三方 MD5 实现
  icons/
scripts/check.mjs           # 静态检查入口
scripts/release.ps1         # 打包、归档检查和校验和
release.bat                 # Windows 发布入口
dist/                       # 生成的 ZIP 和 SHA-256 文件
```

### 新增网盘适配器

1. 在 `src/providers/` 增加模块，导出：
   - `config`：唯一 `key`、显示名 `label`、主页 `homeUrl`、标签匹配 `tabPatterns` 以及适配器自身需要的接口配置。
   - `submitOne(link, dirId)`：提交单条链接，返回计入汇总的文件数量；失败抛出异常。凭证缺失/失效统一使用 `NO_TOKEN` / `TOKEN_EXPIRED` 错误码，便于编排层停止后续提交。
   - `getAuthStatus(state)`：从已保存状态生成凭证状态字段，不向 UI 暴露原始凭证。
2. 在 [适配器注册表](<src/providers/index.mjs>) 导入并注册模块。状态聚合和 UI 根据注册表及状态动态生成，不需要在面板里复制一个网盘分支。
3. **登录同步尚未插件化**：新增网盘还必须更新 [网盘内容脚本](<src/content/drive.js>) 的站点识别与凭证读取，并更新 [manifest.json](<manifest.json>) 的匹配规则和必要权限。仅注册适配器不会自动取得登录态。
4. 运行静态检查，再按本文的浏览器回归步骤验证成功、普通失败、凭证失效、目录覆盖和状态显示。不要将真实 Token 或个人链接写入源码。
